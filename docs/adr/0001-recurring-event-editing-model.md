# ADR 0001: 繰り返し予定の編集モデル

## Status

Accepted

## Context

カレンダーアプリでは繰り返し予定（毎日・毎週・毎月）をサポートする。
繰り返し予定の編集方法として、以下の選択肢を検討した。

1. **シリーズ全体変更のみ** — 単一インスタンスの変更は不可。DB スキーマは最も単純。
2. **Google Calendar 方式（採用）** — 「この予定のみ」「以降すべて」「すべて」の3択で変更できる。例外インスタンス (ExceptionInstance) の概念が必要になる。
3. **単一インスタンス変更のみ** — シリーズの変更は常に例外を生み出す。

## Decision

**Google Calendar 方式**を採用する。

「この予定のみ」「以降すべて」「すべて」の3択で編集・削除できる。

これに伴い、DB スキーマは以下の構造を持つ。

- `recurring_series` テーブル — 繰り返しシリーズのひな形と繰り返しルールを保持
- `events` テーブル — 単発予定と例外インスタンスの両方を保持。`recurring_series_id` と `original_date` を持つことで例外を識別する

「以降すべて変更」は、元のシリーズの終了日を変更日の前日に設定し、変更日以降を新しいシリーズとして切り出すことで実現する。

## Consequences

- DB スキーマが繰り返しシリーズ用テーブルを必要とし、単発予定だけの実装より複雑になる
- 「以降すべて変更」は新シリーズを生成するため、シリーズの数が増えていく可能性がある
- ユーザー体験は Google Calendar に近く、直感的
